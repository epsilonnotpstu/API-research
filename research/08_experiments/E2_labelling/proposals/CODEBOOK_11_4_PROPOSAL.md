## 11.4.1 কখন search আবশ্যক

⚠️ প্রস্তাব: প্রথমে request/response, effective spec এবং checker policy মিলিয়ে কোন **message/constraint**-এর attribution হচ্ছে তা নির্ধারণ করতে হবে। তারপর নিচের ক্ষেত্রে intent search আবশ্যক:

| L1 candidate / পরিস্থিতি | কী করতে হবে |
|---|---|
| Intent-এর উপর নির্ভরশীল `SPEC` বা `SPEC_PARTIAL` | Finalize করার আগে search; বিশেষত `S-STATUS`, explicit guard-নির্ভর `S-REQ-STRICT`/`S-REQ-LOOSE`, serialization-নির্ভর `S-RESP-MISSING`/`S-RESP-TYPE`। একই যুক্তি `S-METHOD`, `S-RESP-VALUE`, `S-CONFIG`-এ ব্যবহার করলেও gate প্রযোজ্য। |
| Code দেখে `IMPL` বনাম `SPEC` আলাদা করা যাচ্ছে না; `UNDECIDABLE`/`both_candidate` আছে | Search করতে হবে; code-এর একটি deliberate-looking return/annotation/guard দেখে SPEC করা যাবে না। |
| Intent-নির্ভর `IMPL` candidate; spec ও code বিরোধী এবং test/doc/commit বা অন্য policy site সিদ্ধান্ত বদলাতে পারে | একই search করতে হবে; শুধু spec-কে authoritative ধরে IMPL দেওয়াও যথেষ্ট নয়। |
| পুরোনো label-এর rationale একটিমাত্র code line; source/spec/checker version বদলেছে; labeller disagreement | প্রযোজ্য evidence আবার যাচাই বা version-matched search reuse করতে হবে। পূর্বের supervisor label labeller নিজে বদলাবে না; review proposal দেবে। |

এটি **সব** SPEC/IMPL label-এর prerequisite নয়। Global schema contradiction, strict-only oracle failure, malformed documented JSON, অথবা নির্দিষ্ট ENV/5xx rule যদি intent না জেনেই message নির্ধারণ করে, সেই rule ও witness cite করলেই হবে। তবে একই cluster-এর আলাদা intent-নির্ভর message-এ search লাগবে। ভিত্তি: codebook `08_experiments/R1_triage_codebook.md:146–152,159–175,177–192,199–204,264–274`। ⚠️ এই gate পুরোনো R3-র “constraint খুঁজে পাইনি” থেকে SPEC করার shortcut-ও রোধ করবে: search absence intent-এর positive প্রমাণ নয়।

⚠️ Search-এর unit হবে `method + template + scenario + status/field/constraint + source/spec revision`। একই operation-এর success ও validation-error scenario আলাদা। সব cluster-এ নতুন subprocess বাধ্যতামূলক নয়: একই unit ও একই hashes-এর সংরক্ষিত search reuse করা যাবে, কিন্তু প্রত্যেক row-তে তার locator ও নিজস্ব scenario mapping থাকবে। Message labels থেকে cluster aggregation বর্তমান §9.1/§10.4 অনুযায়ী হবে; একটি সমর্থিত message দিয়ে গোটা cluster-কে SPEC করা যাবে না (`08_experiments/R1_triage_codebook.md:159–175,228–231`)।

⚠️ Invocation template: `/usr/bin/python3 -I -B 08_experiments/tools/intent_evidence.py SOURCE_DIR SPEC --method METHOD --path TEMPLATE --status STATUS --json`। Field প্রশ্নে `--field FIELD` যোগ/ব্যবহার করুন; `--status`-এ representative exchange-এর observed status দিন, desired status নয়। প্রতিটি relevant status/field proposition-এর run আলাদা record-এ রাখুন। Stdout JSON ও stderr/exit code নিজের task-এর অনুমোদিত evidence directory-তে সংরক্ষণ করুন; প্রথমে concrete paths যাচাই করুন। Exact CLI contract: `08_experiments/tools/intent_evidence.py:866-905`; এই কাজের সাতটি executed argv: `09_collab/logs/T33_scratch/search_summary.json:$[*].command`।

## 11.4.2 Search order ও independence gate

**ক্রম: `HANDLER → E-TEST → E-DOC → E-CONSIST → E-HISTORY`।** এটি retrieval/review order; evidence authority-এর নতুন ranking নয়। E-DEV/fix-এর direction ও attribution যাচাইয়ের বর্তমান নিয়ম বহাল (`08_experiments/R1_triage_codebook.md:38–70,185–191`)। Tool এই ক্রমে candidates সাজায়; history hit স্বয়ংক্রিয় vote দেয় না (`08_experiments/tools/intent_evidence.py:809–851`; `09_collab/reports/T26_report.md:3–11`)।

⚠️ Labeller নিচের পাঁচ ধাপ সম্পূর্ণ করবে। প্রথম favourable hit-এ থামবে না। Local tool-এর বাইরে manual search লাগলে শুধু task-অনুমোদিত source ব্যবহার করবে; blind key, mutation identity বা অন্য labeller-এর সিদ্ধান্ত intent evidence নয়।

1. **HANDLER — context, independent নয়।** Method/path, base prefix, controller, call chain, exception mapper, DTO, media type এবং observed branch trace করতে হবে। একটি return, `@ResponseStatus`, `WRITE_ONLY`, explicit guard, অথবা runtime response সেই আচরণের অস্তিত্ব দেখায়; নিজে তার intended হওয়া প্রমাণ করে না। Tool-এর `HANDLER` ও `E-CODE-INTENT` একা independent requirement মেটায় না। ভিত্তি: `08_experiments/R1_triage_codebook.md:265–274`; tool DTO context: `08_experiments/tools/intent_evidence.py:650–668`।
2. **E-TEST — linked expected behaviour।** Assertion-টি একই operation, method, version, relevant input/auth/state এবং branch-এর status/field policy assert করছে কিনা দেখতে হবে। Test helper-এর prefix ও fixture resolve করে locators দিতে হবে। Same-module হওয়া যথেষ্ট নয়; অন্য module-এর test হলে controller/class, REST base path, helper/call chain বা অন্য যাচাইযোগ্য linkage আবশ্যক। **Linkage-হীন other-module/UI tests কখনো independent evidence নয়।** একটি test-এর repeated assertions বা code থেকে mechanically নেওয়া expectation-কে বহু স্বাধীন প্রমাণ বলা যাবে না। Tool-এর ±10 lines, suffix এবং module flags কেবল candidate gate (`09_collab/reports/T26_report.md:8,60–64,90`; `08_experiments/tools/intent_evidence.py:697–730`)।
3. **E-DOC — proposition ও operation-এর স্পষ্ট সম্পর্ক।** README/API guide/changelog-এর সংশ্লিষ্ট row/paragraph ও branch condition পড়তে হবে। **Proximity-only doc hit কখনো evidence নয়:** পাশের operation-এর 404, success row-এর পাশে validation row, field নামের incidental mention, HTML width বা সংখ্যামাত্র নয়। অন্য module-এ রাখা REST guide গ্রহণযোগ্য হতে পারে; file location দিয়ে বাতিল করা যাবে না। Input OAS তার নিজের independent evidence নয়; তার generated copy-ও নয়। Javadoc/`@ApiResponse` tool-এ E-DOC হলেও একই questioned code/spec-এর পুনরুক্তি হলে independent বলে নেওয়া যাবে না; আলাদা normative statement ও provenance দরকার। ভিত্তি: `09_collab/reports/T26_report.md:9,41,62–66,84`; `08_experiments/R1_triage_codebook.md:265–274`। ⚠️ শেষ provenance gate-টি এই proposal-এর conservative ব্যাখ্যা; প্রশ্ন 4-এ supervisor-এর সিদ্ধান্ত চাওয়া হয়েছে।
4. **E-CONSIST — একাধিক independent policy site।** শুধু একই numeric status নয়: একই rejection/serialization নীতি, সংশ্লিষ্ট conditions ও operation linkage দেখাতে হবে; প্রত্যেক site-এর locator দিতে হবে। Repeated traffic ও একই line-এর একাধিক hit policy independence নয়। Tool distinct class গোনে; labeller সেই সংখ্যা দিয়ে স্বাধীনতা ধরে নেবে না। বর্তমান codebook দুই আলাদা exception handler-এর precedent গ্রহণ করে, একই class-এর বাইরে হওয়ার শর্ত দেয়নি (`08_experiments/R1_triage_codebook.md:269,280`)। Tool same-class methods গোনে না (`09_collab/reports/T26_report.md:10`)। ⚠️ সেই precedent preserve করে অনুরূপ নতুন same-class cases adjudication-এ পাঠানো প্রস্তাব করছি; সাধারণ threshold প্রশ্ন 3-এ।
5. **E-HISTORY — explicit change intent।** Local commit subject hit পেলে commit message ও relevant patch/parent পড়তে হবে; exact behaviour, version এবং fix-এর দিক cite করতে হবে। Issue/changelog কেবল অনুমোদিতভাবে পাওয়া থাকলে ব্যবহারযোগ্য; এই T33 কাজ network-free। `git log -S` occurrence বা merge subject একা intent নয়। History candidate-এ support খালি থাকে; manual review-এ আলাদা independent evidence মিলতে পারে (`09_collab/reports/T26_report.md:11,51`; `08_experiments/tools/intent_evidence.py:827–841`)।

⚠️ **Independence checklist:** (a) expected behaviour স্পষ্ট? (b) target scenario-র সঙ্গে linkage আছে? (c) queried line/spec থেকে আলাদা evidential basis আছে? (d) applicable revision? (e) contrary evidence review হয়েছে? প্রত্যেক accepted hit-এ এই সিদ্ধান্তের সংক্ষিপ্ত কারণ থাকবে। Snippet-এর বাইরে file context পড়তে হবে; tool snippet সর্বোচ্চ 160 characters (`09_collab/reports/T26_report.md:7`)। একই statement-এর translated/generated copies corroboration হিসেবে থাকবে, independent count বাড়াবে না।

## 11.4.3 Tool verdict থেকে label: দুই ধাপের সিদ্ধান্ত

⚠️ **ধাপ A: raw output অপরিবর্তিত সংরক্ষণ।** `independent_evidence`, hits, `scan`, `history`, warnings ও exit status রাখতে হবে। `independent=true`, `counts_toward_verdict=true` এবং `evidence_types_found` tool-এর hypotheses; labeller-এর acceptance নয়। Verdict সব independent-marked support-এর union থেকে হয়; majority vote নয় (`08_experiments/tools/intent_evidence.py:848–863`)।

⚠️ **ধাপ B: প্রতিটি hit review করে label।** Accepted independent evidence implementation-এ observed আচরণকে intended দেখায় এবং effective spec তার বিরোধী হলে **may label SPEC**; evidence code/spec-এর বাইরে intended তৃতীয় আচরণ দেখালে দুই দিক আলাদা করে adjudication চাইতে হবে। Codebook L1 সংজ্ঞা: `08_experiments/R1_triage_codebook.md:29–36`; independent gate: একই file `264–274`।

| Raw tool verdict | বর্তমান tool-এর অর্থ | প্রস্তাবিত label action, review সাপেক্ষে |
|---|---|---|
| `supports_code` | অন্তত একটি candidate supplied observed status বা tentative code field policy-র সঙ্গে মেলে; opposite support নেই। | Verified independent evidence observed implementation-কে intended এবং spec-কে ভুল/অসম্পূর্ণ দেখালে **SPEC হতে পারে**। Spec-ও একই আচরণ অনুমোদন করলে এই proposition-এ defect নেই; অন্য failure message পরীক্ষা করতে হবে। |
| `supports_spec` | অন্তত একটি candidate observed/code behaviour-এর বিপরীতে spec behaviour সমর্থন করে। | সেই scenario-তে যাচাই হলে সাধারণত **IMPL হতে পারে**। **SPEC হতে পারে শুধু manual review-এ উল্টো attribution প্রতিষ্ঠিত হলে**, যেমন raw hits অপ্রাসঙ্গিক এবং বাদ পড়া independent evidence implementation-কে সমর্থন করে; override-এর কারণ বাধ্যতামূলক। Raw string থেকে SPEC স্বয়ংক্রিয় অনুমতি নেই। |
| `conflicting` | Candidates-এর union-এ দুই দিকের support আছে; একই operation-এর আলাদা branches-ও এই ফল ঘটাতে পারে। | Attribution-সংক্রান্ত প্রকৃত conflict অমীমাংসিত থাকলে **UNDECIDABLE + `both_candidate=true`**। ব্যতিক্রম: (i) method/scenario/version/module/proximity ভুল প্রমাণ করে hits বাতিল করলে এক দিক অবশিষ্ট; (ii) applicable developer fix/explicit supervisor adjudication conflict মেটায়; (iii) অন্য প্রতিষ্ঠিত message rule primary IMPL/TEST/ENV নির্ধারণ করে। প্রতিবার locator-সহ resolution লিখতে হবে; শুধু বেশি hits/confidence conflict মেটায় না। |
| `none_found` | কোনো candidate decisive directional support দেয়নি; hits বা history candidate থাকতেও পারে। | Directed manual fallback শেষে independent intent না থাকলে **UNDECIDABLE**। একমাত্র deliberate-looking code/annotation-ই ভিত্তি হলে **`both_candidate=true`**, confidence ≤2 (§11.1–11.2)। Tool যা মিস করেছে তা manual-এ independent intent দিলে যথাযথ SPEC/IMPL সম্ভব; raw verdict অপরিবর্তিত থাকবে। অন্য decisive rule থাকলে তা প্রযোজ্য; absence থেকে SPEC/IMPL নয়। |

উপরের raw semantics-এর প্রমাণ: `08_experiments/tools/intent_evidence.py:670–695,848–863`; branch ambiguity: `09_collab/reports/T26_report.md:41,84`; one-line abstention ও confidence cap: `08_experiments/R1_triage_codebook.md:271–274`। ⚠️ `none_found`-এ code-only intent প্রশ্নও না থাকলে `both_candidate` স্বয়ংক্রিয় true নয়; কেন flag দেওয়া বা না দেওয়া হয়েছে লিখতে হবে।

⚠️ Search incomplete, parse error, unreadable relevant file, unresolved route বা unavailable relevant history-কে `none_found` হিসেবে স্বাভাবিকীকরণ করা যাবে না। Manual coverage দিয়ে gap না মিটলে intent-based decision defer করতে হবে। ইতিবাচক independent প্রমাণ আছে কি না এবং incomplete অংশে বিপরীত প্রমাণ থাকার সম্ভাবনা review note-এ লিখতে হবে। Current timeout/skip/error contract: `09_collab/reports/T26_report.md:43,49–51`; `08_experiments/tools/intent_evidence.py:535–601,866–905`।

**`both_candidate` ≠ BOTH।** Flag uncertain dual attribution-এর review signal; codebook অনুযায়ী final BOTH শুধু supervisor দিতে পারেন। পৃথক প্রমাণিত message defects-এর aggregation এবং primary 5xx/ENV precedence বহাল (`08_experiments/R1_triage_codebook.md:159–175,188–192,217–219`)।

## 11.4.4 Label CSV ও audit record-এর প্রস্তাবিত format

বর্তমান E2 labeller CSV-তে `item_id,L1,L2,proposed_L2,confidence,evidence_types,evidence_locators,root_cause_id,both_candidate,rationale` আছে; final export-এ আলাদা `final_L1/source` আছে। প্রমাণ: `08_experiments/E2_labelling/batch2_baseline_s1_labels_codex.csv:1`; `08_experiments/E2_labelling/market_baseline_s1_labels_codex.csv:1`; `08_experiments/E2_labelling/final_labels_baseline_s1.csv:1`। ⚠️ Existing files rewrite না করে ভবিষ্যৎ labeller sheet-এ নিচের format প্রস্তাব করছি; codebook §6-এর `label_L1/label_L2/evidence_codes/note` নাম ব্যবহার করলে একবার ঘোষিত header mapping দিতে হবে (`08_experiments/R1_triage_codebook.md:120`)।

| Column | প্রস্তাবিত মান / অর্থ |
|---|---|
| `L1`, `L2`, `confidence`, `both_candidate`, `rationale` | Existing decision fields। `both_candidate` = `true/false`; inference-এ ⚠️; rationale-এ evidence কেন কোন দিক সমর্থন করে এবং conflict কেমন মিটেছে। |
| `evidence_types` | Accepted evidence codes, `;` separated। `E-CODE-INTENT` context, `E-TEST`, `E-DOC`, `E-CONSIST`, `E-HISTORY`/`E-DEV`-এর verified basis আলাদা। Tool category blindly copy নয়। E-TEST/E-HISTORY reporting vocabulary-র adoption-ও এই draft-এর অংশ। |
| `evidence_locators` | সিদ্ধান্তে ব্যবহৃত context + accepted evidence-এর repository-relative locators; `;` separated। কোন locator context/independent তা audit record-এ থাকবে। |
| `intent_search_status` | `complete`, `incomplete`, `not_run`। `complete` = tool scan complete এবং scenario review/fallback সম্পন্ন; সব possible evidence খুঁজে ফেলার দাবি নয়। `not_run`-এ প্রযোজ্য rule/reuse-unavailable কারণ cite করতে হবে। |
| `intent_search_verdict` | Raw `supports_code`, `supports_spec`, `conflicting`, `none_found`; run না হলে বা verdict-হীন error হলে `NA`। |
| `intent_review_verdict` | `supports_impl_behavior`, `supports_spec_behavior`, `conflicting`, `none_found`, `not_applicable`। এটি reviewed intent direction; L1 label নয়। |
| `intent_search_locator` | Immutable raw JSON + manifest-এর locator; reuse হলে একই record cite। |
| `intent_review_locator` | প্রতিটি hit-এর accept/reject/context/unresolved সিদ্ধান্ত ও manual additions-সহ review record-এর locator। |

⚠️ **Locator grammar:** text/source = `repo/relative/file.ext:LINE` বা `:START-END`; structured spec = `repo/relative/spec.json#/paths/~1v1~1users/post/responses` (JSON Pointer-এ `/` → `~1`, `~` → `~0`); CSV = `repo/relative/labels.csv:item_id=B065`; JSONL = `repo/relative/exchanges.jsonl:3027`; saved tool hit = `repo/relative/search.json:$.hits[1]`। Tool `location` source-root-relative, তাই label-এ `source_root` prepend করতে হবে। Commit = `source_root@FULL_COMMIT_SHA:relative/file:LINE` plus saved message/patch locator; issue/doc URL থাকলে retrieval date ও saved excerpt locator দিতে হবে। Current web confidence ≤2 বহাল (`08_experiments/R1_triage_codebook.md:185–187`)।

⚠️ Audit manifest-এ থাকবে: `item_id`, message/violation path, method/template, observed status/field direction ও representative exchange locator, `source_root`, source revision বা reviewed-file SHA-256, spec/tool SHA-256, exact argv, exit code, scan/skips/warnings/history availability। Review record-এ **প্রতিটি tool hit-এর index/locator**, `disposition`, reason, scenario/linkage/provenance; manual hits একই format-এ। Accepted ও rejected hits দুটোই রেখে raw verdict override traceable করতে হবে। কোনো hit unresolved হলে সেটি গোপন করে reviewed verdict decisive করা যাবে না।

Worked row-এর অর্থ, CSV-তে এখন লেখা হচ্ছে না: B065-এ `L1=SPEC`, `L2=S-STATUS`, `both_candidate=false`, `intent_search_verdict=none_found`, `intent_review_verdict=supports_impl_behavior`; accepted `E-TEST` হবে `08_experiments/_external/emb/jdk_8_maven/cs/rest/original/scout-api/api/src/test/java/se/devscout/scoutapi/UsersIntegrationTest.java:59-64`, helper linkage locator নিচের উদাহরণে। ⚠️ এটি proposed reporting illustration; frozen baseline row-এর নতুন version নয়।

## 11.4.7 ⚠️ Supervisor-এর খোলা সিদ্ধান্ত — options
