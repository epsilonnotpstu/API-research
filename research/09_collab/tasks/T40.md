## Requirements
1. **`08_experiments/E4_triage/build_e4_blind.py`**, standard library + existing repo tools only. Run it with `/usr/bin/python3 -I -B`.
   - **Inputs:** the four labelled seed-1 baselines listed in E4_PLAN.md, `E2_labelling/final_labels_baseline_s1.csv` (+ adjudication sheets for item↔fingerprint mapping), the EMB specs and SUT sources (read-only), and `tools/specmut.py` + `tools/conformance.py` + `tools/attribute.py`.
   - **Composite spec per SUT.** Apply REQUEST_LOOSE, REQUEST_STRICT, RESPONSE_ORACLE and METHOD_SEM to **disjoint** operation sets with a fixed seed (20261115):
     - Severity: e.g. 30 per class, or a fixed small number of ops per class. Choose it and document the reason; prefer ops that the baseline traffic actually exercises, so that replay can produce items.
     - Use specmut's own selection, `--only-ops` / `--exclude`, and the mutators. Do not re-implement mutations.
     - Record the complete manifest: every op, fault and edit.
     - ⚠️ METHOD_SEM moves an operation to another verb. Make sure later faults cannot select the moved op, and that the composite is still a valid spec, i.e. it parses with the checker.
   - **Replay:** check the baseline `exchanges.jsonl` against (a) the original spec and (b) the composite spec, with the current checker (`INT_FORMATS=True`, default oracle). Then `attribute(..., 'replay')` with the composite manifest.
     - **Injected items:** NEW on a mutated op whose kind ∈ `pilot_results/fuzzer_compare.py` `EXPECTED_KINDS[fault]`. Take at most 3 per SUT×fault, chosen deterministically, preferring different edit pointers.
     - **Decoys:** PERSISTENT fingerprints present under both specs that map to a `final_labels_baseline_s1.csv` item. Take at most 6 per SUT, stratified deterministically by final_L1.
     - Report the counts per SUT×fault, including zeros (LOOSE is expected to be small).
   - **Example exchange per item:** pick a transport-clean representative, with no control bytes in path, query or headers, as `build_e5_blind.py` does. Auth must be redacted. Verify that no Authorization or Cookie value, and none of the auth fixture values, appear anywhere in the package.
   - **Package layout:** `08_experiments/E2_labelling/e4_blind/`:
     - `items.csv`, with columns like e5_blind_v3 (`item_id, package, run, kind, method, template, status, pointer, message, example_exchange`);
     - `K01..K04/`, a shuffled package name per SUT, using a salt. Each contains:
       - `source/`: the original SUT source, copied without target/ or VCS, like `build_e5_blind.py` does;
       - `spec.json`: composite only. **Never** include the original spec.
       - `r1/exchanges.jsonl` and `r1/compose.log`.
     - Item IDs shuffled with the salt.
   - **Key:** `08_experiments/E4_triage/e4_key.csv`, with columns `item_id, role (injected|decoy), sut, fault, expected_L1, expected_L2, edit_pointers, fingerprint, final_L1 (decoys)`. Plus `e4_manifest.json` (the composite manifests) and a `build_log.json` (input hashes, counts, seed, salt).
   - **Refuse to overwrite** existing output.
   - **Blinding checks:**
     - Files **we** generate in the package (`items.csv`, `spec.json`, the TASK files, and the exchanges/compose copies) must not contain the strings `specmut`, `mutation`, `manifest`, `E4`, `E5`, `codemut` or `inject` (case-insensitive word match; report any legitimate hit from the SUT's own traffic text instead of altering it).
     - The `source/` trees are exempt from the string check, because they must be byte-identical to the original EMB sources. Assert this with a hash.
     - The spec must not carry any `x-` extension added by us.
