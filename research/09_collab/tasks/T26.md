# T26 — `intent_evidence.py`: systematic intent-evidence search for attribution (Codex, write + tests)

Read `09_collab/PROTOCOL.md` first. Effort: high.

## Why
- Codebook v0.5 §11 accepts an intent-based SPEC (or IMPL) argument only with **independent intent evidence**:
  - a test that asserts the status or field;
  - documentation, README or API guide;
  - a commit or issue;
  - the same policy at several independent sites.
- In a blind study (results not yet available to you), two labellers diverged on one item only because one of them found a documentation file (an HTML template describing the REST API) and the other did not.
- We want a deterministic search step that every labeller runs, and every labeller cites.

## Deliverable: `08_experiments/tools/intent_evidence.py`
- **CLI:**
  ```
  intent_evidence.py SOURCE_DIR SPEC --method GET --path /products [--status 418] [--field name] [--json]
  ```
- **Steps, in this order.** Each hit records `category`, `file:line`, a ≤160-char snippet and a `strength` note.
  1. **HANDLER:** locate the handler(s) for method+path.
     - JAX-RS: `@Path`, `@GET` and friends, class + method paths.
     - Spring: `@RequestMapping` / `@GetMapping`… with class prefixes.
     - Report the files and lines that set the status in question (`Response.status(...)`, `ResponseEntity.status`, `@ResponseStatus`, `HttpStatus.X`, numeric literals) or that serialise or ignore the field (`@JsonProperty`, `@JsonIgnore`, `WRITE_ONLY`/`READ_ONLY`).
     - HANDLER hits are **not** independent evidence; they are context.
  2. **E-TEST:** test sources (`src/test/**`, `*Test*.java`, `*IT.java`, other languages' test dirs) that reference the path (literal or path segments) **and** either assert a status (`assertEquals(200`, `.statusCode(`, `status().isOk()`, `HttpStatus.`…) or mention the field.
     - Report the asserted value.
     - Mark agreement or contradiction with the observed status or field and with the spec.
  3. **E-DOC:** non-code documentation that mentions the path or field: `README*`, `*.md`, `*.adoc`, `*.txt`, `docs/**`, HTML templates (`templates/**`, `*.html`), Javadoc on the handler, OpenAPI annotations (`@ApiResponse`, `@Operation`).
     - Extract the status codes or field names mentioned near the path (window ±10 lines).
  4. **E-CONSIST:** other handlers or exception mappers that produce the same status for analogous situations (the same `HttpStatus`/numeric code in ≥2 independent classes), or the same field annotation pattern on ≥2 DTOs.
     - Report the count of independent sites.
  5. **E-HISTORY:** if `SOURCE_DIR` is inside a git work tree, run `git log -S<literal> --oneline` limited to the handler file (read-only).
     - Otherwise report `unavailable` explicitly.
     - Never fetch anything over the network.
- **Output:** a summary verdict field with one of these values:
  - `independent_evidence: supports_code` (an independent source agrees with the code's behaviour);
  - `supports_spec` (an independent source agrees with the spec, contradicting the code);
  - `conflicting`;
  - `none_found`.
  - Also list which §11.1 evidence types were found.
- **Constraints:** standard library only; deterministic ordering; must run on large trees in < 30 s (skip `target/`, `node_modules/`, `.git/`, binaries).
