## Fix 1 — ordering false positive (scout-drop-null s3)
`mitmproxy-container.json` `Config.Env` and `HostConfig.Binds` hold the same entries in a different order. Docker ordering is not stable.

Compare `Env` as a multiset. Compare `Binds` as a set, after replacing each run's own run directory with a placeholder. Keep every other setting strict, and apply the same rule to the SUT container.

## Fix 2 — generator asymmetry on a NON-mutated operation (cwa pairs, s2)
Schemathesis reports a JUnit Schema Error, "Invalid `RegistrationTokenRequest` definition", for `POST /version/v1/registrationToken`.
- It appears in the control run but not in the mutant run. Same spec, same seed: it is generator nondeterminism.
- **Root cause:** the spec has `"required": false` inside a property schema, `keyDob`. This is invalid JSON Schema, a real spec defect.

New rule in `validate_pair.py`:
- **Identical errored sets:** PASS, as now.
- **Differing sets, and every differing operation is NOT in the manifest's mutated operations:** status `PASS_WITH_EXCLUSION`.
  - List the excluded `(method, path)` and the reason.
  - `analyse_pair.sh` and `summarise_e5.py` must drop those operations from **both** roles' counts, for the mutated and the non-mutated totals.
  - Add `excluded_ops` and `validation_status` columns to the summary.
- **Any differing operation that is mutated:** FAIL.
