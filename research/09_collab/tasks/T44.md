## Requirements
1. **`08_experiments/E6_realfix/build_e6_blind.py`** (stdlib + read-only `git --git-dir`). Inputs:
   - `combined_accepted.csv`;
   - the bare clones in `/run/media/afridi/Shared Data/api_research_upstream/*.git` and `08_experiments/_external/upstream/*`.
2. **One package per item** (`K01..K25`, shuffled with a salt) under `08_experiments/E2_labelling/e6_blind/`:
   - `source/`: the **parent-commit** tree, restricted to what a reviewer needs, to keep size sane:
     - the contract file(s);
     - the module(s) containing the operation's handler, DTOs, validators and exception mapping;
     - that module's tests;
     - top-level README/docs.

     Document the inclusion rule. Exclude `.git`, binaries over 2 MB, and build output.
   - `contract`: if the contract is a spec file, it lies inside `source/`. Record its path in `items.csv`, and do not copy it twice.
   - `items.csv`: `item_id, package, operation, proposition, contract_locator_hint` (path only, no line-level hint of what changed).
     - Copy the proposition **verbatim** from `combined_accepted.csv`.
     - Claude reviewed the propositions for neutrality. Do NOT add context about the fix.
   - **No** fix commit, commit messages, dates, `evidence`/`proposition_check` columns, or any child-commit content.
3. **Leakage checks (assert them):**
   - (a) No package file equals the fix-commit version of any changed path, unless it is identical at the parent.
   - (b) **Cross-item leakage:** for items from the same repo, if item A's fix commit is an ancestor of item B's parent and any of A's fix-changed paths are included in B's package, then B's package would reveal A's resolution. Report each such pair, and resolve it by excluding those paths from B **only if** they are not B's own contract/handler files. Otherwise drop the later-sorted item, and record it as excluded from the scored set.
   - (c) No CHANGELOG, release note or issue text in any package mentions an item's fix (re-run the T43 parent-leakage scan on the actual package files).
   - (d) No credentials: run the existing scans and the auth-fixture value checks. No author names or emails: redact attribution trailers if any appear in docs.
   - (e) The generated files (`items.csv`, the TASK files) do not contain `fix`, `commit`, `later`, `changed`, `E6`, `mined`, `T42` or `T43` as words. Source files are exempt.
4. **Key:** `08_experiments/E6_realfix/e6_key.csv`, with columns `item_id, truth_direction, repo, stars, confidence, contract_kind, mismatch_type, fix_family, source_task`. Also write `e6_build_log.json`, with hashes and the inclusion and exclusion decisions.
5. **Task drafts** in `e6_blind/`, adapted from `E2_labelling/e4_blind/TASK_M1.md` and `TASK_M2.md`:
   - **Wording:** there are no runtime exchanges. The labeller judges from the parent source + contract + proposition. The question is which artifact deviates from the intended behaviour: L1 ∈ {SPEC, IMPL, TEST, ENV, UNDECIDABLE} (M2 may also use SPEC_PARTIAL/IMPL_PARTIAL/DEFERRED per codebook).
   - **M2:** copy `E2_labelling/e4_blind/CODEBOOK_v0.6.md` unchanged. The intent tool (`../../tools/intent_evidence.py`) is allowed. The package has no VCS, so history scope = unavailable.
   - **Both tasks:** keep the launch authorization line (see the e4 TASK files), the explicit-path search rule, the redaction rule, the no-cross-package-comparison rule ("do not compare files across packages"), and the output files `labels_<ID>.csv` + `report_<ID>.md` (+ `review_<ID>/`, `search_<ID>/` for M2).
6. **Tests:** `08_experiments/E6_realfix/test_build_e6_blind.py`. Cover determinism, the leakage assertions on synthetic repos, and refuse-to-overwrite.
7. **Run the production build once.** Report the sizes and any dropped items.
