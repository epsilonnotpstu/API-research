## Requirements

### 1. Retrieval: direction-neutral (this differs from T43)
Reuse the T42/T43 pipeline (`08_experiments/E6_realfix/scripts/`, `t43/`) **read-only**. Write new code under `08_experiments/E7_mining/`.

- **Candidate condition:** a correction cue (fix/correct/align/match/mismatch/wrong/missing/incorrect/inconsistent/conform/according to spec/docs/…) **and** the commit changes a contract path **or** a behaviour path.
- **Ranking:** must not prefer either direction. Give no bonus for "behaviour without contract change", and no bonus for "contract-only".
  - Rank by the cue strength and the presence of an operation-specific path. Then sort: repo, score descending, SHA ascending.
  - Freeze the pool (`candidate_pool.json`) before review.
- **Exclusions as in T42:** merges, reverts, releases, dependency bumps, mass reformatting, generated-only churn, new endpoints and features.

### 2. Manual review: identical to T42/T43
- Neutral parent-state proposition: `"<METHOD> <path>: contract says <X>; implementation does <Y>"`, with no hint of which side changed later.
- `proposition_check` with parent locators only; `evidence`; confidence 1–3; `contract_kind`; `mismatch_type`; `fix_family`; `truth_direction` ∈ {SPEC, IMPL, BOTH}.
- For IMPL acceptance, the PARENT contract must already state the behaviour the fix implements.
- **Do not target or balance directions.** Review in rank order, and accept whatever passes the gate.
- **Per-repo cap:** 6 accepted items per repo. When a repo reaches the cap, stop reviewing it.
- **Stopping rule:** stop at ≥45 new accepted items in total, or when every repo has had its top 30 ranked candidates reviewed (or its cap reached).
  - Report the stopping reason, and how many candidates were reviewed per repo.
- **Dedup:** against `08_experiments/E6_realfix/combined_accepted.csv`, by repo + operation + fix family.

Also write `key/accepted_full.csv`, with full evidence and message excerpts.

### 4. Parent-state excerpt package
Write it to `08_experiments/E2_labelling/e7_blind/`. Item IDs are `X01..Xnn`, shuffled with a salt that is stored only in the key directory.
- **`items.csv`:** `item_id, repo, operation, proposition`. The proposition is copied verbatim.
- **Per item, `Xnn/contract/`:** the parent contract.
  - A spec file: the whole file if ≤300 KB. Otherwise the operation object plus every component it transitively `$ref`s, as valid YAML/JSON, with a note naming the source path.
  - Annotation-based: the annotated source file(s).
- **Per item, `Xnn/impl/`:** the **whole parent-state files** for every implementation locator in `proposition_check`, plus files directly needed to read them: the called guard, validator, helper or exception mapper in the same repo, at most 8 files per item.
  - Keep the repo-relative paths in the directory structure.
- **Never include:**
  - fix-version content of any changed path (unless it is byte-identical at the parent);
  - commit messages, SHAs, dates, CHANGELOG or release notes;
  - attribution trailers, author names or emails (redact them);
  - credentials (run the T44 scans).
- **Cross-item check:** for items from the same repo, if item A's fix commit is an ancestor of item B's parent, and a file in B's package was changed by A's fix, set `cross_item_flag` in the key for B. Exclude that file from B unless it is one of B's own locator files.
- **Forbidden words** in `items.csv` (whole words, case-insensitive; source excerpts are exempt): fix, fixed, commit, later, changed, mined, repair, direction, E6, E7, T42, T43, T45.
