## Goal
Separate two questions that the validator now conflates:
1. **Run-time provenance:** was the run produced by an identified, unmodified harness and tool snapshot? Show this from the hashes recorded in `run.json` and the run artefacts, and from the pair checks (equal non-jar inputs, argv equality, and so on). This must remain strict: control and mutant (or control and control_repeat) must have **identical** recorded harness and tool snapshots.
2. **Analysis-time tools:** the checker and attribution used *now* may differ from run time.
   - The summary must record the analysis tool hashes, e.g. `analysis_tool_sha256` or a single digest column.
   - It must also record whether they differ from run time, e.g. `analysis_tools_drift: none|changed`.
   - Do not silently PASS: drift is reported, not hidden.
