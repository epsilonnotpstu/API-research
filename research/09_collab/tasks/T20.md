## Deliver (in `08_experiments/E5_codemut/`)
1. **`run_pair.sh MUT_DIR [SEEDS…]`.** Runs control and mutant via `harness_v2/run_pilot.sh` per your README "Future paired harness runs". Default seeds are 1 2 3.
   - Keep `DATA_GEN=all` and `SCHEMA_CHECKS=response_headers_conformance`, with budget 300 s.
   - Write the run directories to `MUT_DIR/runs.tsv`.
   - If a run fails, record it and stop.
2. **`validate_pair.py CONTROL_RUN MUTANT_RUN MUT_DIR`.** Implements every check in README "Pair validation". Writes `MUT_DIR/pair-validation-s<seed>.json` with PASS/FAIL per check, and exits non-zero on any FAIL.
3. **`analyse_pair.sh MUT_DIR`.** For each validated seed, implements README "fresh analysis and independent attribution":
   - Both oracles (market: SUT oracle 400/406/422).
   - Uses `tools/conformance.py --deploy-origin http://$SUT_SERVICE:$INTERNAL_PORT`.
   - Uses `tools/attribute.py --mode fresh` with the code manifest.
   - Output goes under `MUT_DIR/analysis-s<seed>-<oracle>/`.
4. **`summarise_e5.py`.** Builds one CSV row per pair × seed × oracle:
   - NEW, VANISHED, INCREASED, DECREASED on the mutated operations, plus the same counts on non-mutated operations as a noise estimate.
   - Whether the manifest's expected conformance signal was observed.
   - The triage L1 for the NEW violations on mutated ops, if `tools/triage.py` applies; check its CLI.

   Output: `E5_codemut/e5_summary.csv`.
5. **Tests:** synthetic tests for `validate_pair.py` and `summarise_e5.py`, written as fake run directories.
