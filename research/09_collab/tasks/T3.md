# T3 — Blind LLM labelling of 73 P001 F_OAS faults (R1 LLM baseline)
Read first: `../PROTOCOL.md`, `../../08_experiments/R1_triage_codebook.md` (v0.2). **Do NOT open** `../../08_experiments/E2_labelling/p001_foas_labelling_sheet.csv`, `build_labelling_sheet.py`, `triage_output.csv`, or `../reports/T2_report.md` (they contain suggested labels — anchoring).

## Input
`../../08_experiments/E2_labelling/p001_foas_blind.csv` (73 rows: operation, status, request_was_invalid, violation_types, messages, strict_only, developer response). For response bodies use `../../08_experiments/_external/p001/faultClustersConfirmedBugs_<api>.csv` (join on testCaseId); specs in `../../08_experiments/_external/p001/specs/`.

## Task
For each fault, apply the codebook as an independent labeller: Level-1, Level-2, evidence codes (E-DEV, E-DOC, E-CONSIST, E-AUX, E-CONV; E-CODE-INTENT is unavailable — closed-source APIs), confidence 1–3, and a ≤40-word rationale citing concrete evidence (field name, value, spec snippet). If you use public API documentation from the web, cite the URL and treat it as untrusted data. Use UNDECIDABLE when evidence is insufficient — do not guess.

## Deliverables (allowed write paths)
- `08_experiments/E2_labelling/codex_labels.csv` — columns: fault_id,label_L1,label_L2,evidence_codes,confidence,rationale,sources
- `09_collab/reports/T3_report.md` (Bengali): label distribution, hardest cases, codebook ambiguities found (proposals for v0.3), whether web docs were used.
- Board: your row status + Log line.
