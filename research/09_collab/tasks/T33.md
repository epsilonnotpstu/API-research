# T33 — Codebook §11.4 proposal: intent-evidence search procedure (Codex, draft only)

Read `09_collab/PROTOCOL.md` first. Effort: high.

## Context
Codebook v0.5 §11 (`08_experiments/R1_triage_codebook.md:261-…`) requires **independent** evidence for an intent-based SPEC label:
- independent means a test, doc, commit, or multiple sites;
- a single code line gives UNDECIDABLE plus both_candidate.

`08_experiments/tools/intent_evidence.py` (T26 + T26b, installed 2026-11-15) automates the search:
- order HANDLER → E-TEST → E-DOC → E-CONSIST → E-HISTORY;
- verdicts `supports_code` / `supports_spec` / `conflicting` / `none_found`.

Held-out results on blind v2 packages are in `09_collab/reports/T26_report.md` and its T26b addendum.

## Task
Draft a **proposal** for a new codebook section, §11.4 "Intent-evidence search procedure". This is the supervisor's decision: it is NOT adopted, so do not edit the codebook. Cover:
1. When a labeller must run the search: which L1 candidates and which situations.
2. The search order. What counts as independent evidence, and what never counts:
   - handler code;
   - other-module tests without linkage;
   - proximity-only doc hits.
3. How tool verdicts map to label decisions:
   - `supports_spec` → may label SPEC;
   - `conflicting` → UNDECIDABLE plus both_candidate, unless …;
   - `none_found` → … .
   - The tool is an aid, not an oracle. The labeller must review every hit and cite locators.
4. The reporting format for evidence in the label CSV: column names and locator format.
5. Worked examples from existing **non-blind** material only: the E2 baseline labels, `FINAL_LABELS.md`, the T26 smoke cases. Do NOT open blind packages or keys: `E2_labelling/e5_blind*/K*`, `blind_key*`, items under labelling.
6. Known tool limitations (from the T26/T26b reports) and how a labeller compensates.
7. ⚠️ Open questions for the supervisor, as a numbered list with options.
