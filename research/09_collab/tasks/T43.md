## Requirements
1. **Reuse your T42 pipeline** (`08_experiments/E6_realfix/scripts/`), extended. Do not rewrite the T42 outputs; write new files with a `t43_` prefix, or a `t43/` subdirectory.
   - Keep the T42 accepted set frozen. The final set = T42 ∪ T43, deduplicated by repo + operation + fix family.
2. **IMPL-targeted heuristic** (document it):
   - Commits that change behaviour surfaces **without** touching the contract surface of the same operation, where the message or diff indicates conformance to the documented contract. For example:
     - wrong status (`return 404 instead of 500`, `ResponseStatus`, exception mapping);
     - missing validation of a documented required field;
     - optional parameter handled as required (null guard / NPE fix);
     - serialization of a documented field (`@JsonProperty`, `@JsonInclude`, nullable);
     - content type;
     - pagination/defaults as documented.
   - Spec-first repos (generated interfaces from an OpenAPI file) are especially useful. A delegate/impl change that leaves the YAML untouched, and fixes behaviour to match it, is IMPL. A YAML-only change that re-describes existing behaviour is SPEC.
   - Keep the SPEC-direction candidates too, but prioritise review effort to reach balance.
3. **Manual review protocol: identical to T42.**
   - Neutral parent-state proposition template.
   - `proposition_check` locators.
   - Confidence 1–3.
   - Reject features/new endpoints, refactors, generated-only churn, and fixes whose "contract" is only a test or a client.
   - **For IMPL acceptance, require evidence that the contract (spec file or annotations) at the PARENT already stated the behaviour that the fix implements.**
4. **Target:** review until **≥16 IMPL accepted** in the combined set, or until every repo's ranked pool is exhausted to a stated depth (at least the top 20 ranked candidates per repo). Report the stopping reason.
5. **Popularity and leakage:**
   - Record stars, as Claude will give them (`t43_repo_meta.csv`, provided below).
   - Flag items whose fix commit is referenced by a CHANGELOG, release notes or issue text that exists **in the parent tree**. That is future leakage if we package the parent; it should be impossible, but check.
6. **Outputs:**
   - `08_experiments/E6_realfix/t43/{candidates.csv,accepted.csv,summary.json,README.md}`;
   - `08_experiments/E6_realfix/combined_accepted.csv` (T42 + T43, deduplicated; with a column `source_task`);
   - `09_collab/reports/T43_report.md` (Bengali; technical terms in English);
   - one board Log line.
