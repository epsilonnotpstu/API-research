## Deliverables (all under `R4_access_control/mining/`; Python 3 standard library only; each script runs as `/usr/bin/python3 -I -B mining/<script>.py` from `R4_access_control/`)
1. **`r4_common.py`**: shared helpers.
   - **`run(cmd)`:** subprocess wrapper with retries (3, with backoff) for `gh` and `git` network commands.
   - **Contract-path detection.** The T50 rule (plan §3.1). Export `is_contract_path(path) -> bool`.
   - **Source-path detection.** Export `is_source_path(path) -> bool`: `.java`, `.kt` or `.go`. Exclude:
     - any path segment in the excluded set of §3.1;
     - `src/test/`;
     - `_test.go`;
     - `/test/` and `/tests/` segments.
   - **`is_test_path(path)`:** test files of any language (`src/test/`, `_test.go`, `/test/`, `/tests/`, `*Test.java`, `*Tests.java`, `*Test.kt`, `*IT.java`).
   - **Annotation detection.** Load `../R3_silent_breaking/mining/annotation_patterns.json` read-only and extend the JVM names with `SecurityRequirement`, `SecurityRequirements` and `SecurityScheme`. Export `annotation_lines(diff_text) -> int`: the number of added or removed diff lines that match.
   - **`sha256_file`**, and canonical JSON writing (sorted keys, LF).
2. **`r4_collect.py`.**
   - Fetch advisories with `gh api --paginate "/advisories?ecosystem=<eco>&type=reviewed&cwes=<list>&per_page=100"` for eco in (maven, go), with the CWE list of §3.
   - Cache the raw pages in `mining/cache/advisories_<eco>.json`.
   - Write `mining/advisories.json`: a normalised list sorted by `ghsa_id`, with fields:
     - `ghsa_id`, `cve_id`, `ecosystem`, `cwes` (sorted ids);
     - `severity`, `published_at`, `withdrawn_at`;
     - `summary`, `description`;
     - `references` (list, in order);
     - `source_code_location`;
     - `packages` (names).
   - Skip withdrawn advisories (reason `WITHDRAWN`).
   - Print counts only. Never print advisory text.
3. **`r4_resolve.py`.**
   - **Candidates.** For each advisory, parse the commit references (regex `^https://github\.com/([^/]+)/([^/]+)/commit/([0-9a-fA-F]{7,40})`). Order them as in plan §3: references to the `source_code_location` repository first, then the rest.
   - **Fetch.** Per repository, keep a bare partial clone at `mining/cache/git/<owner>__<repo>.git`, created with `git init --bare` and `git remote add origin https://github.com/<o>/<r>.git`. For each candidate SHA, run `git fetch --depth=2 --filter=blob:none origin <sha>`.
   - **Short SHAs.** For a SHA shorter than 40 characters, first resolve it with `gh api repos/<o>/<r>/commits/<sha> --jq .sha`.
   - **Choice.** The first candidate that fetches is the fix. Record `fix_sha`, `parent_sha` (`git rev-parse <fix>^1`; if there is no parent, the reason is `NO_PARENT`) and `repo`.
   - **Exclusion.** If no candidate resolves, the reason is `NO_COMMIT`.
   - Write `mining/resolved.json`: `ghsa_id` → resolution record, or reason.
   - Network failures must be retried, then recorded as `FETCH_ERROR` (never silently dropped).
4. **`r4_pool.py`.**
   - Apply the eligibility rules of §3.1–§3.3 using `git ls-tree -r --name-only <parent>` and `git diff --numstat <parent> <fix>`. These read only trees and numstat; blobs are lazily fetched for the numstat.
   - Apply the dedup rule of §3, keyed on `(repo, fix_sha)`.
   - Write `mining/pool.json` (eligible items with mechanical fields) and `mining/pool_inventory.json` (counts per exclusion reason, per ecosystem and per repository).
   - Write `mining/pool_freeze.json`: the sha256 of `advisories.json`, `resolved.json`, `pool.json` and `pool_inventory.json`, plus the query parameters.
   - Refuse to overwrite an existing freeze.
5. **`r4_sample.py`.**
   - Implement §3's sampling exactly.
   - Write `mining/sample.json` and `mining/sample_freeze.json` (sha256 of `sample.json` plus the pool freeze hash).
   - Refuse to overwrite.
6. **`r4_build.py`.** Build the packages of §4.
   - **Inputs.** It reads the sample; item ids come from an HMAC-SHA256 shuffle with a fresh 32-byte salt stored in `mining/key/r4_shuffle_salt.txt`. Item ids are `A001`…, in shuffled order.
   - **`packages/r4_blind/`.** Item folders, `items.csv` (item_id, repo_short_name, language), and `TASK_R4.md` (copied from `plan/TASK_R4.md`; do not read it, just copy it).
   - **Claude batches.** `packages/r4_kb1` … `r4_kbK` with 16 items each, in item-id order, each with its own `items.csv` and `TASK_R4.md` copy.
   - **`item.md`.** The repository short name, language, CWE ids, advisory summary and description, and the list of touched source files.
     - Redact URLs containing `/commit/`, `/pull/`, `/compare/` or `/releases/`, and GHSA/CVE links: replace them with `[LINK]`.
     - Redact lines that credit reporters: `credit`, `thanks`, `reported by`, `discovered by`, `found by` (case-insensitive) become `[CREDIT REDACTED]`.
     - Redact e-mail addresses.
   - **`diff.patch`.** `git diff <parent> <fix> -- <source files>`, with no commit header.
   - **`before/` and `after/`.** The touched non-test source files, up to 20 (largest-change first). Paths are flattened with `__`.
   - **`contract/`.** As in §4: the 3 largest contract documents at the parent, each truncated to 3,000 lines, plus `INDEX.md`.
   - **Privacy and secret scan.** Reuse `../R3_silent_breaking/mining/t53_privacy.py` (import read-only via `sys.path`), or reimplement its redaction for emails and credential prefixes. Any secret finding redacts the token and is logged by kind (never its value).
   - **`mining/key/r4_key.csv`.** Columns: `item_id`, `ghsa_ids` (`;`-joined), `repo`, `ecosystem`, `language`, `fix_sha`, `parent_sha`, `cwes`, `severity`, `published_at`, `fix_lines`, `fix_touches_contract`, `fix_touches_annotation`, `fix_silent`, `test_in_fix`, `n_contract_docs`.
   - **`mining/key/r4_build_log.json`.** Per-item notes and scan counts by kind.
   - Language is decided by the majority extension of the touched source files.
   - Refuse to overwrite an existing `packages/r4_blind`.
7. **`test_r4.py`.** Synthetic offline tests:
   - Build a temporary git repository with known commits (contract and source files, test files, a large diff) and use it as `origin` via a `file://` URL.
   - Cover `is_contract_path`, `is_source_path`, `is_test_path` and `annotation_lines`.
   - Cover resolve ordering (source repository first; short SHA resolution can be mocked).
   - Cover each eligibility reason and the dedup.
   - Cover sampling determinism and the cap.
   - Cover redaction of links, credits and emails in `item.md`.
   - Check that build output contains no commit message or author.
   - Check that every script refuses to overwrite its frozen output.
   - Run with `/usr/bin/python3 -I -B mining/test_r4.py`; all tests must pass.
