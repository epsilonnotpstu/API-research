# Blind contract review — G3

Reviewed all 102 items in `items.csv` order using only this package. No item code was executed, no network or git history was used, and no files outside this directory were read. All item advisories, patches, and contract directories were accessible.

The CSV records 56 PRESENT, 31 ABSENT, 9 UNCLEAR, and 6 NO_CONTRACT decisions. Locators are relative to each item's directory. Empty locator/quote fields mean not applicable or unavailable.

Hard cases and conventions:

- **Base documents:** C001 and the NiFi items C028/C032/C063/C071 contain service-specific base metadata or generation configuration but no operation paths. I coded operation coverage ABSENT. Security schemes in those documents alone do not establish coverage of an operation.
- **Different services:** C019/C025/C039/C062 supply OpenChoreo agent contracts rather than contracts for the affected API server or cluster-gateway. C087 supplies bundled Argo CD contracts rather than Devtron Attributes. These are NO_CONTRACT for the affected service.
- **Unrendered template:** C078's nonempty Authelia document contains Go template directives and is not a directly parseable OpenAPI document; the other document is empty. I coded NO_CONTRACT. No template was executed or rendered.
- **Unresolved references:** C038 lists the affected durable-task path at `contract/api-contracts__openapi__openapi.yaml:54`, but its operation is an external `$ref` to a fragment absent from the supplied directory. The contract's HTTP method and any security override cannot be verified, so coverage and policy are UNCLEAR and security is NA.
- **Shared middleware or unavailable routing:** Concrete operations remain UNKNOWN for C007, C009, C014, C021, C022, C024, C031, C045, C047, C052, C056, C059, C061, C063, C070, C072, C078, C090, C093, and C100. These involve deployment-defined proxy rules, portlets, generic middleware, or handlers without their route registrations. Unrelated documented operations were not substituted for the affected operation.
- **Broad surfaces:** C002 enumerates the changed vulnerability-triage and asset-version write routes. C016 lists writes using the patched shared-pipeline checker, excluding the separately reported multipart-upload flaw C034. C025/C062 record the supplied gateway proxy URL template with the read and mutation methods described in the advisory. C073 covers REST reference/metadata operations and S3 copy; C018's S3 operation is distinguished by the `delete` query parameter, omitted from the operation path field.
- **Workflow controller flaws:** C003/C088 can be reached by workflow submission through Argo's REST API or Kubernetes resource creation. The Argo creation operation is documented, but the specific Strict/Secure override restriction is not. C057's deployment-destination and resource restrictions are derivable from AppProject schemas; the deletion endpoint does not restate them.
- **Method mismatch:** C008 documents POST import with the administrator OAuth scope. Export is documented as GET, while the advisory names POST. PRESENT is supported by import alone.
- **Mixed findings:** C084 includes the additional flaws explicitly listed in the item. Its policy YES relies on the documented registration-disable setting for account creation; the reaction-deletion operation does not itself state creator ownership. C033's YES relies on the project schema's explicit allowed source namespaces. C049's YES relies on the denied-file policy forbidding retrieval of restricted content; copying was the bypass.
- **Undefined authentication scheme:** C099 explicitly says the user-list operation requires authentication, supporting policy YES. Its `ApiKeyAuth` requirement has no scheme definition in either supplied document, so security is NOT_DECLARED under the task's defined-scheme requirement.
- **Authentication versus authorization:** Bearer/API-key declarations alone were not treated as evidence of ownership, tenant membership, action scopes, administrator-only fields, or revocation semantics. For missing-authentication flaws such as C010/C083, an applicable defined security requirement does state the violated rule.
