## 1. Candidate pool (pool4)
**Window.** Non-merge commits reachable from each repo's HEAD (first-parent default branch), with committer date from 2023-01-01T00:00:00Z inclusive to HEAD.

**A commit is a candidate if all of the following hold:**
1. **Behaviour file.** It modifies (adds, modifies or deletes lines in) at least one **behaviour-path** file. Use your T46 definition: Java, Kotlin or Go production server source (handlers, controllers, resources, routes, DTOs, models, validators, serializers, error mapping). Exclude test, example, sample, generated, vendored, migration, build and CI files under your T46/T50 exclusion rules.
2. **No contract document.** It modifies **no** checked-in OpenAPI/Swagger document. Use your T46 document definition: a file with a top-level `openapi`/`swagger` key at parent or child, or a file `$ref`-reached from one at the parent.
3. **Size.** Across behaviour-path files: at most 400 changed lines (added + deleted) and at most 8 files.
4. **Not formatting-only or rename-only.** No behaviour-path file in the commit is only reformatted (whitespace-insensitive diff empty) or renamed with no content change.
   - If any behaviour-path file is formatting-only or rename-only, drop that file from the count.
   - If no behaviour-path file is left, the commit is not a candidate.
5. **Not a bot.** The author name or email does not match `dependabot`, `renovate`, `github-actions` or a `[bot]` suffix.
   - Check this in a scratch process.
   - **Never write author names, emails or any other personal attribution to any file or log.** Record only a boolean count of excluded bot commits per repo.

**Freeze before opening any candidate.**
- Write `R3_silent_breaking/mining/pool4.json`. For each candidate it holds: repo, sha, parent sha, committer date, behaviour-path file list, changed-line count, language.
- Write `mining/freeze4.json`. It holds the pool hash, the hash of the code that built it, the heads hash, and `"before_sampling": true`.
- Report the pool size per repo.
- No patch content may be displayed or read for judgement before the freeze. Building the pool uses only `--numstat`, `--name-status`, the whitespace-insensitive emptiness check and document detection.

## 2. Sample (deterministic)
For each repo, in byte order of the repo name:
- Take the candidate SHAs sorted ascending.
- Draw `random.Random("20261117:" + repo).sample(shas, min(3, len(shas)))`.

Write the sample to `mining/sample4.json`, with its hash in `mining/freeze4_sample.json`, before building any package. Do not resample, replace or skip a sampled commit for any reason except a mechanical build failure (§3). Record such failures; never substitute another commit.

## 3. Packages
**Item IDs.** One item per sampled commit, with IDs `Bnnn` (B001…). Shuffle the order with a new salt stored only in `mining/key/r3_shuffle_salt.txt`.

**Create `R3_silent_breaking/packages/r3_blind/`.** Refuse to overwrite it if it exists. It contains:
- **`items.csv`:** LF line endings; columns `item_id,repo,language,files`, where `files` is the behaviour-path files separated by `;`.
- **Per item `Bnnn/`:**
  - `item.md`: repo name, language, touched behaviour-path files. Nothing else.
  - `diff.patch`: `git diff parent..sha` restricted to the behaviour-path files. Strip the commit header, message, author, date and index lines; keep only file headers and hunks.
  - `before/<path>` and `after/<path>`: full parent and child versions of those files. A deleted or added file has only one side.
  - `contract/`: the parent's checked-in OpenAPI document(s).
    - When operations can be mapped mechanically from the touched files, project to those operations plus their `$ref` closure, as in T49/T50. Mapping sources are route strings or annotations in the touched files, or Go swagger comments.
    - Otherwise include the whole document, projected to at most 2,000 lines by your T49/T50 rules.
    - Record the mapping mode in the key.
- **`README.md`:** a short neutral description of the layout. No study purpose.
- **`TASK_R3.md`:** copied byte-identical from `R3_silent_breaking/plan/TASK_R3.md`.

**Privacy and safety:**
- Apply your T49/T50 privacy redaction and display filter to every delivered file: credential-like literals, long encoded literals, emails and personal attribution (`@author` tags, copyright holder lines naming persons, `Co-authored-by` lines).
- Redact by replacing the value with `[REDACTED]`. Never print the original values.

**Leakage.**
- No delivered file may contain the commit SHA, parent SHA, commit message, PR or issue numbers from the message, dates, or author data.
- Run your T49/T50 leakage scans and add these fields.

## 4. Key (in `R3_silent_breaking/mining/key/` only)
**`r3_key.csv`** with at least these columns:

**`annotation_touched` (`true`/`false`).**
- It is `true` if any added or removed line in `diff.patch` contains a JVM contract annotation from your T46 list (OpenAPI/Swagger, JAX-RS and Spring web annotations, Bean Validation constraints, `@ResponseStatus`, `@JsonProperty`/`@JsonIgnore`/`@JsonInclude`, `@Schema`, `@Parameter`, `@ApiResponse(s)`, `@Operation` and the rest of that list).

- Store the exact pattern list you used in `mining/annotation_patterns.json`.

**`spec_updated_90d` (`true`/`false`).** It is `true` if any checked-in contract document of that repo changes in any commit with committer date in (commit date, commit date + 90 days], following first-parent history up to HEAD.
